# 大学校园多智能体平台：面试准备主入口

本文档是面试准备的入口。它负责回答三个问题：这个项目怎么讲、先练哪几段、被追问时去哪里找证据。

## 1. 一分钟项目介绍

我做的是一个学校公选课 Multi-Agent 推荐系统。学生直接用自然语言描述选课偏好，例如"不考试、作业少、给分友好、东校区，周三晚上不要有课"。系统先把自然语言拆成学生画像和硬约束，再从 500 门真实课程中召回候选，经过确定性硬约束过滤和 LLM 语义初筛后，在候选课程内排序、检查容量和时间风险，最后生成可解释的推荐理由。

这个项目的核心思路是"规则保下限、LLM 提上限"。硬约束（校区、时间、考试要求）用纯规则处理，保证确定性；LLM 负责画像抽取、语义初筛、候选内排序和推荐理由生成。编排支持两种模式：固定 Pipeline 延迟可控，ReAct 工具调用模式让 LLM 在异常时可以回头重试。

## 3. 面试主叙事

### 3.1 开场顺序

1. 先讲场景：学生选公选课不是搜索关键词，而是同时考虑兴趣、校区、时间、考核、容量和限制条件。
2. 再讲核心思路：规则保下限——硬约束过滤用纯规则，LLM 不参与确定性判断；LLM 提上限——画像、语义初筛、排序和理由生成交给大模型。
3. 再讲编排：支持两种模式。固定 Pipeline 阶段确定、延迟可预测。ReAct 工具调用模式把 Agent 包装成 7 个工具，LLM 根据中间结果动态决策，硬约束工具锁死不可跳过。
4. 最后讲验证：39 个单测通过、Docker E2E 接口验证、SSE 流式推荐可正常输出。未验证的指标不写。

### 3.2 一句话架构

> 我的系统把 LLM 放在适合它的位置：画像抽取、语义初筛、候选内排序和推荐理由生成。课程事实来自 MySQL，语义召回来自 Milvus，候选缓存来自 Redis。硬约束用规则处理，不让 LLM 商量。编排支持 Pipeline 和 ReAct 两种模式，通过 A/B 分流。

### 3.3 三个必须讲清的取舍

- **规则保下限、LLM 提上限**：硬约束（校区、时间、考试）用规则保证确定性，排序和理由用 LLM 提升语义理解。500 门课全量塞给 LLM 理论上更好，但单次上万 token 经济性不可靠，规则做 safety net 更务实。
- **Pipeline 和 ReAct 为什么并存**：Pipeline 延迟可控，适合大部分请求。ReAct 在异常时（召回不足、全爆满）可以回头重试，但 token 成本随轮次增长、延迟不可预测。两种模式通过 A/B 实验对比。
- **硬约束为什么锁死不可跳过**：用户说"只要西校区"时推荐东校区是不可接受的。硬约束过滤在 ReAct 模式中也是唯一不可跳过的工具——如果 LLM 没调，编排器强制补调。

## 4. 按岗位切换侧重点

### AI Agent 方向

重点讲：ReAct 工具调用设计、LLM 语义初筛、双模式 A/B 对比、硬约束锁死、Agent 失败 fallback 链

### 后端工程方向

重点讲：asyncio 并行调度、Redis 缓存设计（精确+语义+短锁）、embedding 冗余消除、评分职责分离、SSE 流式状态机

### 推荐系统 / RAG 方向

重点讲：四类 chunk 设计、MySQL+Milvus+Redis 三层召回、Milvus 距离融入排序、宽+精双路召回、Phase 1.5+1.75 分层过滤

## 5. 训练路径

### 第一轮：讲顺

- 用 `docs/interview-star-stories.md` 的前 3 个故事练 60 秒口播
- 要求：不超过 90 秒，不连续堆 3 个技术名词，每 20 秒都能听到"为什么"或"我做了什么"

### 第二轮：讲细

- 用 `docs/code-walkthrough.md` 练代码证据链
- 要求：能从 `main.py` 讲到 Supervisor，再讲到 ReAct 工具、HardConstraintFilter、CourseRecallAgent
- 能画出 Phase 1→1.5→1.75→2→3 的依赖关系

### 第三轮：被追问

- 用 `docs/interview-question-bank.md` 练追问
- 要求：每题先给一句结论，再给一个代码或验证证据，最后承认一个真实边界

## 6. 不要这样讲

- 不要说"实现了高并发推荐系统"，当前没有压测数据
- 不要说"CTR 提升 15%"，没有真实用户实验结果
- 不要把 Redis 说成"实时学生画像"，当前是召回候选缓存
- 不要说"全量生产可用"，A/B 的 ReAct 组还没注册，metrics 是进程内实现
- 不要说"Agent 之间有对话协商"，当前是 Supervisor 调度，Agent 间没有直接通信
- 不要隐瞒 LLM 参与度：核心召回、硬约束、初始评分是工程代码，LLM 参与画像/排序/理由
