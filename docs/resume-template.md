# 简历 Bullet 与口播模板

本文档只放可直接用于简历和面试口播的表达模板。完整 STAR 故事见 `docs/interview-star-stories.md`，追问训练见 `docs/interview-question-bank.md`。

## 1. 写简历前的边界

可以写：

- 公选课推荐、教务选课场景、自然语言偏好
- Supervisor + ReAct 双模式编排、A/B 实验分流、5 个 Agent + 硬约束过滤
- 硬约束确定性过滤（Phase 1.5）、LLM 语义初筛（Phase 1.75）、候选内重排
- MySQL 课程主表、Milvus chunk 语义召回、Redis 候选缓存 + 语义缓存
- 召回-重排评分职责分离、Milvus COSINE 距离融入排序
- embedding 冗余消除（3 次降 1 次）、语义缓存误命中修复（阈值 0.95）
- FeasibilityAgent LLM 个性化抢课建议（priority_advice）
- Docker、FastAPI、SSE 流式推荐、marker parser 状态机
- 已验证的测试结果：39/39 单测通过、Docker E2E 接口验证

不要写：

- 真实用户 CTR、CVR、GMV、P99 延迟等没有验证的数据
- "百万级高并发""生产级推荐平台"等没有压测或上线证据的表述
- "Redis 实时学生画像"，当前主线是召回候选缓存
- "全量 500 门课程已在当前环境稳定导入"，除非当次环境已验证
- "ReAct 模式已上线 A/B"，当前 A/B 未注册 react group

## 3. 简历 Bullet 模板

### 版本一：AI Agent / 大模型应用

```text
• 设计并实现学校公选课 Multi-Agent 推荐系统，支持学生用自然语言描述兴趣、校区、时间、考核偏好，系统从 500 门课中召回、过滤、排序并生成可解释推荐
• 实现 Supervisor Pipeline 与 ReAct 工具调用双模式编排，通过 A/B 实验分流；ReAct 模式下 LLM 可根据召回结果动态决定是否放宽条件重试，硬约束过滤工具锁死不可跳过
• 在召回后插入 Phase 1.5 确定性硬约束过滤和 Phase 1.75 LLM 语义初筛，将 ~150 门候选缩减至 40 门送入重排，兼顾确定性安全和语义理解深度
• 每个 Agent 有独立的 LLM 调用策略和规则 fallback：画像失败走启发式、重排失败走规则评分、理由失败走字段拼接、抢课建议失败静默回退规则
```

### 版本二：后端 / 工程能力

```text
• 基于 FastAPI 实现同步/SSE 流式双接口，Supervisor 按依赖关系用 asyncio.gather 并行调度 Agent，Phase 3 理由 token 通过 marker 状态机归属到课程
• 封装 Agent 基类统一处理耗时记录、指数退避重试和 fallback；消除召回路径 embedding 冗余调用（3 次降 1 次），统一在入口计算向量后传递给三个消费者
• 设计 Redis 召回缓存：精确 key + 语义近邻（同结构化签名桶内 cosine ≥ 0.95）+ 分布式短锁防击穿；修复语义缓存误命中（1152 维向量句式模板区分度不足，阈值 0.9→0.95）
• 实现召回-重排评分职责分离：召回只保留关键词匹配 + 热度，重排用 _compute_score() 融合 profile 偏好与 Milvus COSINE 距离（乘法放大器 final = profile_score × (1 + sim × 0.5)）
```

### 版本三：推荐系统 / RAG

```text
• 构建"MySQL 结构化过滤 + Milvus 语义召回 + Redis 候选缓存"三层课程召回架构，宽召回 + 画像精召回双路合并保证广度
• 将课程 CSV 拆分为 basic/schedule_capacity/learning_profile/audience_tags 四类 chunk，避免整行 embedding 字段语义稀释，提升"作业少、不考试"等需求的命中精度
• 实现 Phase 1.5 确定性硬约束过滤（校区/类别/时间/考试）+ Phase 1.75 LLM 语义初筛（从 ~150 门中挑出语义相关 Top 40），确定性过滤与语义理解分层执行
• 设计重排评分公式融入 Milvus 向量相似度：profile_score × (1 + cosine_sim × 0.5)，让语义召回信号参与最终排序而不只是决定召不召回
```

## 4. 60 秒口播模板

```text
我做的是一个学校公选课 Multi-Agent 推荐系统。学生直接说选课偏好，比如"不考试、作业少、东校区，周三晚上不要有课"，系统从 500 门课中召回候选、过滤硬约束、排序，最后生成推荐理由。

核心设计是规则保下限、LLM 提上限。硬约束过滤用纯规则——校区不对就删掉，不让 LLM 商量。LLM 负责画像抽取、语义初筛、候选内排序和推荐理由生成，每个环节失败都有规则 fallback。

编排上我实现了两种模式：固定 Pipeline 延迟可控，适合大部分请求；ReAct 模式把 Agent 包装成 7 个工具，LLM 在召回不足或全爆满时可以回头重试。两种模式通过 A/B 实验分流。

数据层把课程拆成四类 chunk 存 Milvus，Redis 缓存候选 ID 不缓存课程事实，MySQL 始终是事实源。

当前不足也比较明确：时间冲突仍偏轻量，A/B 的 ReAct 组还没注册，真实业务指标需要上线后补充。
```

## 5. 3 分钟展开模板

```text
这个项目解决的是学生选公选课时"自然语言偏好 + 真实课程约束"难以同时处理的问题。学生说"轻松、给分友好"是语义需求，"东校区、周三晚上不要"是硬约束，"热门但可以冲"是风险偏好。

系统拆成 Supervisor + 多个 Agent。Phase 1 画像和宽召回并行，画像完成后用结构化字段补充精召回，两次合并保证广度。Phase 1.5 硬约束过滤先挡掉违规课程——这里用纯规则，不用 LLM，因为校区、考试这些约束错一个就是糟糕体验。Phase 1.75 如果候选还有一两百门，LLM 看每门课一行摘要挑出语义相关的 40 门。Phase 2 重排和可行性并行，最后 Phase 3 生成推荐理由。

评分上我做了职责分离。召回阶段只保留关键词匹配和热度，负责广度；重排阶段用 _compute_score 融合 profile 偏好和 Milvus 的 COSINE 距离——向量相似度作为乘法放大器放大 profile 分，让语义命中的课程排序更靠前。

除了 Pipeline，我还实现了 ReAct 编排模式。把 5 个 Agent 和硬约束过滤包装成 7 个工具，LLM 根据中间结果决定下一步。正常走直线，异常时可以回头——比如召回不足时自己再调一次宽召回。硬约束工具锁死不可跳过。两种模式通过 A/B 实验分流。

Redis 缓存也做了语义近邻：结构化条件相同时比较 prompt embedding，但修复了一次误命中——"我对计算机感兴趣"命中了"心理学"缓存，原因是 1152 维向量对句式模板区分度不足，阈值从 0.9 提到 0.95。

验证上，39 个单测通过，Docker E2E 接口验证正常。真实业务指标还没有，简历上不会写 CTR 或延迟提升。
```

## 6. Bullet 自检

- [ ] 每条 bullet 有具体动作对象，不只写"使用了 RAG"
- [ ] 结果只写能证明的现象或测试，不写虚构指标
- [ ] 能区分"我负责的改动"和"项目已有能力"
- [ ] 技术栈后面能讲出为什么用它，不只罗列
- [ ] 能说清 Pipeline 和 ReAct 的区别
- [ ] 对真实未知数据使用"待补充"
