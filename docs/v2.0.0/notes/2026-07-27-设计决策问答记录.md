## 第 3 轮 · 决策 3：deepagents vs OpenAI Agents SDK

**问题**：deepagents 还是 OpenAI Agents SDK？两者差异很大：deepagents=LangGraph+文件系统+subagents；OpenAI Agents SDK=官方 handoffs/guardrails/MCP（有 TS 变体但无文件系统）。

**选项**：
- A. deepagents(推荐) —— 建在 LangGraph 之上，保留平台能力+额外获得文件系统+TodoWrite+subagents
- B. OpenAI Agents SDK —— 官方 handoffs/guardrails/MCP，有 TS 变体但无文件系统

**用户选择**：✅ A deepagents

## 第 7 轮 · 决策 7：Skills 系统架构 + 报告生成 skill 方案

> 本轮先被用户拒绝、要求澄清；用户要求「参考优秀源码后回答」。我派 Explore agent 只读分析了 `E:\Agent\` 下 4 个参考项目（pi/claude-code/OpenMAIC/FastGPT）的真实代码，综合结论后重提。

**问题**：参考 4 个优秀项目源码后，决策 7 选哪个？（源码 unanimously 指向 A）

**选项**：
- A. 原生 tools+单模型双渲染(推荐·源码印证) —— Skills=原生 Python 工具（Pydantic 生成 schema）+ MCP-ready 抽象；报告=LLM 结构化 JSON→Jinja2 HTML + python-docx Word
- B. MCP skills+单模型双渲染 —— Skills 暴露为 MCP server
- C. 原生 tools+HTML 转 Word —— 报告先生成 HTML，再 pandoc/libreoffice 转 Word
- D. 原生 tools+LLM 直出双格式 —— LLM 分别生成 Word/HTML 内容

**源码调研关键结论**：
- Skills 注册：pi/claude-code/OpenMAIC/FastGPT 4 项目**全部以原生 in-process 工具为主**，MCP 仅作外部能力可选层，无一当主机制
- 文档生成：4 项目**均无原生 Word/PDF 生成**（pi 无；claude-code 靠 Bash+pandoc；OpenMAIC 仅 PPTX/ZIP；FastGPT docx/pdf 只读解析+前端 html2pdf）
- 渲染哲学一致偏向「结构化数据→目标格式」硬映射

**用户选择**：✅ A 原生 tools+单模型双渲染（4 项目源码印证）

## 第 8 轮 · 决策 8：跨语言 TS 含义

> 本轮经历多次澄清。第一轮用户选「MCP 桥接 TS skill」后要求重提；第二轮用户澄清真实意图。

**用户澄清的真实意图**：「我的意思是，一方面前端确实有甚至要上 VUE 框架，这个后续再说，主要是指我接入了 fastgpt 和 pi agent cc 这些项目，可以引用进行二次开发，无需仿造再编写 python，那么就会出现双语言的可能性，这时候就是个问题。」

**问题（澄清后重提）**：Python 主系统如何与二次开发的 TS 项目（FastGPT/pi/cc）跨语言集成？范围放 v2.0.0 还是延后？

**选项**：
- A. MCP 桥接+v2 先接 1 个(推荐) —— TS 项目作独立服务二次开发，Python deepagents 经 MCP 调用（FastGPT 自带 mcp_server）。v2.0.0 先接 1 个 TS 服务
- B. HTTP API 调用 —— TS 项目作独立服务，Python 经 HTTP API（非 MCP）调用
- C. 双 agent 运行时 —— Python deepagents + TS pi 都跑 agent 逻辑
- D. 延后到 v2.1 保 MVP 焦点 —— v2.0.0 暂不集成 TS 运行时

**用户选择**：✅ A MCP 桥接+v2 先接 1 个
