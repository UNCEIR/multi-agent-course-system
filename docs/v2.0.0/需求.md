# Multi-agent 项目升级为V2.0.0的需求设计

## V1.0.0的瓶颈:

 - 这就是一个简陋的rag工程，提示词工程，一个问答然后走知识库重排过滤打分最后流式输出返回；没有真正体现多agent的活性，也没有体现真正agent工程的多方落地参考要素；项目深度不够，无法通过该项目考察开发者的agent应用落地能力。
 - 使用的技术栈过于简陋，可参考多方面市面上的主流框架和api设计，通过github或网页搜索进行一定的了解，优化这个项目的技术栈。
 - 实现核心功能实际就是一个推荐接口--需要新增多个跟学生相关的垂直业务场景，由此扩展出多个接口--例如学生对话中根据他提供的成绩单csv数据，生成一份期末课程报告分析（html/word文档下载链接），各种理性分析+感性回答（评语和鼓励的话语）；这是一个例子，还有许多可列举。比如分析成绩，比如能回答大学领域里面的问题（大学生想要知道学校的一些规章制度，咨询）。

## 项目突出的工程思维要求：

- 目前进度：以完成phase0的落地，功能需求需要新增更改；原有的功能点要求有变动。

- 体现深度：例如做那个通用知识解答的agent，使用E:\Agent\multi-agent-course-system\广东工业大学2025年学生手册.pdf作为数据源，同时具有网页搜索这类的mcp工具功能；这类agent端到端（基本所有涉及的）如何做意图识别，如何做 mcp，如何管理多轮对话的记忆，如何评测端到端 agent，在多 agent 情况下如何做 routing，如何利用 monitor agent 的在线表现，常见的工具调用出错比如检索不全召回不好，该怎么优化。体现一系列跟rag检索策略细节体现具体数据指标，agent的harness包括loop一系列思想，工具调用链路断掉时你怎么处理的，模型幻觉导致错误行动时你怎么兜底的。可以好好想，使用grill-me和brainstorming自己做一些决策，参考同个e盘agent父目录下去其他agent的做法。
- 通用agent可以加入一些跟图谱识别等多模态的llm；接入定制开发的插件

- 想要新增的点：参考OpenMAIC项目；围绕大学生为学校的课程小组ppt汇报这一业务场景，搭建ai生成ppt功能微课件自动生成系统，多agent协作，支持画布，动画，ppt等。用户输入提示词，选择对应类型（期末PPT课设/小组汇报/）。
  
- rag方面需要体现的点：PDF 能不能解析干净，chunk 切分是否合理，检索能不能找到关键内容，Rerank 会不会带来过高延迟，Prompt 能不能稳定输出，最终答案有没有证据可以追踪。根据接下来phase阶段（涉及rag）做的事有对应数据指标，声明问题并提供优化策略。

## 新增需求（2026-08-06）

### 1. skills/tools 公共抽取 + agent 编排分离
- `tools/` 放原子能力实现（PDF 解析、分块、向量化、渲染、搜索、插件），以 `@tool` 装饰器 + Pydantic `args_schema` 暴露，每个 tool 独立 `.md` 说明文档。
- `skills/` 放 **SKILL.md 技能文档**（deepagents SkillsMiddleware 自动加载的渐进式披露指令），每个技能一个子目录 + `SKILL.md`，**不是 Python 代码层**。SkillsMiddleware 扫描目录 → 解析 SKILL.md frontmatter → 注入 system prompt → Agent 需要时 read_file 读全文。
- `tools/` 放原子能力实现 + **工具注册层**（ToolRegistry 放 `tools/registry.py`，CircuitBreaker 放 `tools/circuit_breaker.py`，MCPClient 放 `tools/mcp_client.py`）。`tools/` 是统一的工具管理目录，Skills 只做技能文档说明。
- `agent/` 只做编排（路由/委派/调度/对话管理），不持有具体能力实现。
- 能力实现不散落在 agent 包中，`agent/documents/` 只留编排门面，`parser.py`/`chunker.py` 下放到 `tools/documents/`。

### 2. deepagents 优先，FastGPT 拖拽并存
- Phase 1-2 先用 deepagents 框架编码实现（`create_deep_agent` + `@tool` + ToolNode）。
- Phase 3 起引入 FastGPT 拖拽构建，作为同业务的备选/增强实现。
- 两者不冲突，通过 feature flag 切换（`config/settings.py` 中 `knowledge_provider` 等开关）。
- 拖拽产物（FastGPT app/workflow）对应 Python tool 的配置映射，在 `tools/` 中维护映射表。
- 同一业务可同时有两套实现，编码实现优先交付，拖拽实现后续增强。

### 3. 通用 chat 插件体系
- Phase 3-4 在 `/chat` 主 agent 下逐步扩展插件 tool：
  - **写作**：`writing_assistant` tool（LLM 驱动，支持多体裁/多风格/长文生成）
  - **图片生成**：`image_generate` tool（经 MCP 调图片生成服务）
  - **编程**：`code_interpreter` tool（沙箱执行/代码生成/错误分析）
  - **脑图**：`mindmap_generator` tool（文本→思维导图 DSL→渲染，支持 Markdown/Mermaid/plantuml）
  - PPT 生成：`ppt_generate` subagent（独立场景，多 agent 协作，参考 OpenMAIC）
- 插件走 ToolRegistry 注册 + allowlist 门控，支持 MCP 动态发现接入外部插件。
- 插件工具按 category namespace 分类（如 `image/*`、`code/*`、`mindmap/*`），便于 allowlist 按类别授权。
- Phase 1 预留占位文件（仅签名 + `NotImplementedError`），用于验证 ToolRegistry 扩展性。

### 4. 技能工具架构文档化
- 新增 `docs/v2.0.0/skills-tools-architecture.md`，定义：
  - `tools/` vs `skills/` 分层职责
  - tool 命名规范、输入输出 schema 规范、错误返回规范（`isError` result）
  - MCP tool 与原生 tool 在注册、调用、失败处理上的统一接口
  - circuit breaker 统一包装器与 MCP/subagent 扩展接口
  - tool category/namespace 分类体系
