# Multi-agent 项目升级为V2.0.0的需求设计

## V1.0.0的瓶颈:

 - 这就是一个简陋的rag工程，提示词工程，一个问答然后走知识库重排过滤打分最后流式输出返回；没有真正体现多agent的活性，也没有体现真正agent工程的多方落地参考要素；项目深度不够，无法通过该项目考察开发者的agent应用落地能力。
 - 使用的技术栈过于简陋，可参考多方面市面上的主流框架和api设计，通过github或网页搜索进行一定的了解，优化这个项目的技术栈。
 - 实现核心功能实际就是一个推荐接口--需要新增多个跟学生相关的垂直业务场景，由此扩展出多个接口--例如学生对话中根据他提供的成绩单csv数据，生成一份期末课程报告分析（html/word文档下载链接），各种理性分析+感性回答（评语和鼓励的话语）；这是一个例子，还有许多可列举。比如分析成绩，比如能回答大学领域里面的问题（大学生想要知道学校的一些规章制度，咨询）。

## 参考点：

- 参考E盘下的agent目录openmaic和fastgpt项目，使用这个项目去驱动二次更改定制化的这两个项目，来匹配大学生教务系统这个业务多方面业务的新增功能点。这个项目可以使用openai sdk又或是deepagents框架又或是其他来完善，最终融合成大的agent项目。

## 项目突出的工程思维要求：

- 目前进度：以完成phase0的落地，功能需求需要新增更改；原有的功能点要求有变动。

- 体现深度：例如做那个通用知识解答的agent，使用E:\Agent\multi-agent-course-system\广东工业大学2025年学生手册.pdf作为数据源，同时具有网页搜索这类的mcp工具功能；这类agent端到端（基本所有涉及的）如何做意图识别，如何做 mcp，如何管理多轮对话的记忆，如何评测端到端 agent，在多 agent 情况下如何做 routing，如何利用 monitor agent 的在线表现，常见的工具调用出错比如检索不全召回不好，该怎么优化。体现一系列跟rag检索策略细节体现具体数据指标，agent的harness包括loop一系列思想，工具调用链路断掉时你怎么处理的，模型幻觉导致错误行动时你怎么兜底的。可以好好想，使用grill-me和brainstorming自己做一些决策，参考同个e盘agent父目录下去其他agent的做法。
- 通用agent可以加入一些跟图谱识别等多模态的llm；接入定制开发的插件

- 想要新增的点：参考OpenMAIC项目；围绕大学生为学校的课程小组ppt汇报这一业务场景，搭建ai生成ppt功能微课件自动生成系统，多agent协作，支持画布，动画，ppt等。用户输入提示词，选择对应类型（期末PPT课设/小组汇报/）。
